### ReID 系统前端需求文档（PRD）

## 项目名称
- **ReID 模型配置与结果验证平台**

## 核心模式
- **纯前端展示**（后端以静态数据路径提供 JSON/图片，按参数路径匹配返回）

## 目标
- 提供高度交互式的界面，用于验证不同 ReID 模型与参数配置对检索结果的影响。

---

## 1. 核心流程与页面布局

### 1.1 核心工作流
- **用户操作流**：模型选择 → 参数配置 → 随机目标抽取 → 模态选择 → 执行查询 → 查看结果

### 1.2 页面布局
- **两栏布局**：左侧为配置与输入区，右侧为结果展示区。
  - **A. 配置输入区（左侧）**：模型选择、超参数配置、目标 ID 抽取、查询模态选择
  - **B. 结果展示区（右侧）**：基于当前配置展示 Rank 列表、得分与配置摘要

---

## 2. A. 配置输入区 - 功能需求

### 2.1 模型与参数配置
- **目的**：确定用于查询的 ReID 模型及其工作模式；参数可见性随 `model_id` 动态联动。

- **功能点与交互**
  - **模型选择**（下拉，必选）
    - 选项由接口返回；变更后需动态更新相关参数控件可见性
    - 传输键：`model_id`
  - **滑动窗口**（单选 4/8/16，仅支持时显示）
    - 传输键：`sliding_window`
  - **融合方式**（单选：简单拼接 / MLP 融合 / 注意力融合，仅支持时显示）
    - 传输键：`fusion_method`
  - **MoE 专家选择**（开关，仅支持时显示）
    - 传输键：`use_moe`

### 2.2 目标选择与查询模态
- **目的**：确定查询的目标 ID 与源模态。

- **功能点与交互**
  - **随机抽取 ID**（按钮）
    - 点击后调用接口，获取新的 `target_id` 及三模态图片 URL
  - **目标 ID 显示**（文本标签）
    - 实时展示当前抽取的 ID（如：P_005）
  - **多模态视图**（并排：RGB / NIR / TI）
    - 通过 URL 加载图片；URL 为空则显示“数据缺失”占位
  - **查询模态选择**（三个单选按钮，位于图片下方）
    - 用户必须三选一；选中的模态图片需高亮为查询源
    - 传输键：`query_modality`
  - **执行查询**（主按钮）
    - 收集所有配置，校验后向查询接口 POST；期间进入加载态

---

## 3. B. 结果展示区 - 功能需求

- **目的**：清晰、实时地展示检索结果与指标。

- **功能点与交互**
  - **配置摘要**（结果顶部文本/卡片）
    - 清晰展示生成当前 Rank 列表所依据的完整配置：模型 ID、参数状态、查询模态等
  - **评估指标（可扩展）**（数据卡片）
    - 展示本次查询对应的 `mAP` 与 `Rank-1`（由接口响应提供）
  - **Rank 序列列表**（网格卡片）
    - 展示 Top-N 匹配结果：匹配图片、得分（4 位小数）、时间戳、摄像头 ID
    - 对 Rank-1 结果进行显著视觉强调
  - **加载状态**（进度条/Spinner）
    - 接口调用期间禁用查询按钮并显示加载动画

---

## 4. 前端与抽象后端 API 规范（路径调用模式）

- 每次查询通过参数组合构造唯一键，后端据此定位并返回预存的 Rank List JSON 文件。

### 4.1 数据获取 API
- `GET /api/get_models`：获取所有模型 ID 及其支持的参数列表
- `GET /api/get_random_target_id`：随机获取 `target_id` 及其三模态图片 URL

### 4.2 核心查询 API（Rank List）
- `POST /api/reid_rank_query`：提交模型、参数、目标 ID 与查询模态，返回预存的 `rank_list` 与 `metrics`

#### 示例请求体（JSON）
```json
{
  "target_id": "P_005",
  "query_modality": "NIR",
  "config": {
    "model_id": "Model_A",
    "sliding_window": 8,
    "fusion_method": "attention_fusion",
    "use_moe": true
  }
}
```
