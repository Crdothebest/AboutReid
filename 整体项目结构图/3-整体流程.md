# Multi-Scale MoE 结构图（2025.12 最新代码版）

> 本文只围绕 `modeling/fusion_part/multi_scale_moe.py`、`modeling/make_model.py` 与 `engine/processor.py` 中与 MoE 相关的逻辑，帮助你快速定位“专家网络为何不起作用”“Top-k 为什么没生效”等问题。

---

## 1. 模块结构速览

```
MultiScaleMoE
├── GateFusionConcat (可选，MLP 门控预处理)
├── AttentionFusionConcat (可选，多头注意力预处理)
├── ExpertNetwork × N (默认 N = len(MOE_SCALES) = 3)
│    └─ Linear → GELU → Dropout → Linear → Dropout
├── GatingNetwork
│    └─ MLP + Temperature + Softmax
├── Top-k Routing (soft/hard)
└── Final Fusion (Linear → LayerNorm → GELU → Dropout)
```

> **命名对照**  
> - `GateFusionConcat` 是老的 `MultiHeadAttentionConcat` 改名而来，实际为 MLP。  
> - 真正的多头注意力叫 `AttentionFusionConcat`，通过 `MODEL.USE_ATTENTION_FUSION` 控制。

| 功能 | 位置 | 相关配置 |
| --- | --- | --- |

## 3. 代码走读

### 3.1 ExpertNetwork
- 输入/输出：`[B, feat_dim]`（默认 512）。
- 结构：`Linear → GELU → Dropout` × (`num_layers` - 1) + `Linear → Dropout`。
- `hidden_dim`、`dropout`、`num_layers` 分别由 `MODEL.MOE_EXPERT_HIDDEN_DIM`、`MODEL.MOE_EXPERT_DROPOUT`、`MODEL.MOE_EXPERT_LAYERS` 控制。

### 3.2 GatingNetwork
- 构造函数参数：`input_dim = feat_dim * num_scales`，`temperature`、`dropout`、`num_layers`、`init_weights`。
- 前向输出 `gate_scores`，再除以温度并做 `Softmax` 得到 `[B, num_experts]` 权重。
- 若配置了 `MODEL.MOE_USE_FIXED_WEIGHTS`，则跳过 MLP，直接广播给整个 batch。

### 3.3 Top-k 路由 `_apply_top_k_routing`
| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| `soft`（默认） | Mask 非 Top-k 专家并重新归一化权重，保留梯度 | 与 Load Balancing Loss 更兼容，训练稳定 |
| `hard` | Mask + 重新归一化 + `stop_gradient`，非 Top-k 专家梯度被完全屏蔽 | 需要极致稀疏或推理效率时使用 |

相关配置：`MODEL.MOE_USE_TOP_K_ROUTING`、`MODEL.MOE_TOP_K`、`MODEL.MOE_TOP_K_MODE`。

### 3.4 Final Fusion
`self.final_fusion = nn.Sequential(Linear → LayerNorm → GELU → Dropout)`，对加权求和后的 `[B, feat_dim]` 做一次 MLP，输出给上层（通常是 CLS token 增强 & 多模态融合）。

## 4. 数据流（含 Top-k 与 Fixed Weights）

```
multi_scale_features = [feat_4x4, feat_8x8, feat_16x16]  # 每个 [B,512]
concat = torch.cat(multi_scale_features, dim=1)          # [B,1536]

if use_fixed_weights:
    expert_weights = fixed_weights.broadcast_to([B, num_experts])
else:
    expert_weights = GatingNetwork(concat)               # [B, num_experts]

if use_top_k_routing:
    expert_weights = _apply_top_k_routing(expert_weights)

weighted_outputs = Σ (expert_weights[:, i] * Expert_i(feat_i))
final_feature = FinalFusion(weighted_outputs)            # [B,512]
```

## 5. 日志与调试切入点

| 观察指标 | 来源 | 说明 |
| --- | --- | --- |
| `Experts:[w1,w2,w3]` | `engine/processor.py` Eval 日志 | CURRENT/BEST 两行都会附带 `[w1,w2,w3]`，可确认 Top-k 或固定权重是否生效。 |
| `Training Finished` 汇总 | `engine/processor.py` 末尾 | 展示 `Best Epoch`、`Best mAP / Rank-1/5/10` 以及最佳专家权重，便于回溯。 |
| MoE Loss 权重 | `utils/config_printer.py` | `SOLVER.MOE_BALANCE_LOSS_WEIGHT` 等会在启动前打印，若为 `0.0` 则动态调度会自动跳过。 |

## 6. 常见问题速查

1. **Top-k 没生效？**  
   - 确认命令行为 `MODEL.MOE_USE_TOP_K_ROUTING True`（注意大小写）。  
   - `config_printer` 与 Eval 日志中的专家权重都应反映出稀疏分布。

2. **MoE Loss 仍然输出旧值？**  
   - 检查是否在 YAML 中仍保留了 `MODEL.MOE_BALANCE_LOSS_WEIGHT` 等字段；engine 内的优先级为 `命令行 > YAML > defaults`。

3. **日志里找不到专家权重？**  
   - 说明当前实验没有走 `USE_CLIP_MULTI_SCALE + USE_MULTI_SCALE_MOE`，或 `BACKBONE.current_expert_weights` 没有刷新（可能被 `detach`）。

4. **固定权重实验怎么配置？**  
   - `MODEL.MOE_USE_FIXED_WEIGHTS True` + `MODEL.MOE_FIXED_WEIGHTS [0.4,0.3,0.3]`。  
   - `config_printer` 会显示 “固定权重模式 FixedWeights = ✅ ENABLED, Weights = [...]”，Eval 日志也会看到不变的 `Experts:[…]`。

## 7. 配置示例（Top-2 软路由）

```yaml
MODEL:
  USE_CLIP_MULTI_SCALE: True
  USE_MULTI_SCALE_MOE: True
  MOE_SCALES: [4, 8, 16]
  MOE_EXPERT_HIDDEN_DIM: 1280
  MOE_TEMPERATURE: 0.5
  MOE_USE_TOP_K_ROUTING: True
  MOE_TOP_K: 2
  MOE_TOP_K_MODE: "soft"
  MOE_USE_FIXED_WEIGHTS: False
SOLVER:
  MOE_BALANCE_LOSS_WEIGHT: 0.001
  MOE_DIVERSITY_LOSS_WEIGHT: 0.001
  MOE_SPARSITY_LOSS_WEIGHT: 0.0001
```

> **Tips**：若需要与 Top-k 共存的稳定训练，可适当降低 `MOE_BALANCE_LOSS_WEIGHT`，或暂时关闭动态调度。
