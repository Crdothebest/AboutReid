# 文本特征在训练与推理阶段的完整使用流程

> 基于 AboutReid 项目源码逐层分析，面向非代码读者友好叙述
>
> 生成时间：2026.04.07

---

## 〇、一句话总结

本项目为每张行人图像（RGB、NIR、TIR 三种模态）都配备了一段**文字描述**。在**训练阶段**，这些文字被用来帮助模型更好地理解三种模态之间的语义共性；在**推理阶段**，文字被设计用来逐模态地修正视觉特征的薄弱之处——但当前代码中推理阶段的文本使用存在一个尚未修复的传参缺失，导致该功能实际未生效。

## 一、数据层：文本从哪里来？

### 1.1 原始标注的产生

项目使用 **QwenVL**（千问视觉语言模型）自动为每张图像生成一段自然语言描述。例如：

> "The female is wearing a white dress with a black belt"

这些描述以 JSON 文件的形式存储在数据集的 `text/` 目录下，按模态分为三份：

| 文件 | 内容 |
|------|------|
| `train_RGB.json` | 训练集中每张可见光图像的文字描述 |
| `train_NI.json` | 训练集中每张近红外图像的文字描述 |
| `train_TI.json` | 训练集中每张热红外图像的文字描述 |
| `test_RGB/NI/TI.json` | 测试集同理 |

每条记录包含图像文件名和对应描述，模型可以通过文件名精确匹配到对应的文字。

### 1.2 文本预处理：添加"模态身份"

原始描述只是一段通用的文字，并不携带"这段描述来自哪种模态"的信息。为了让后续的文本编码器能感知模态差异，项目对每段描述进行了**模态感知预处理**，具体做了两件事：

**第一步：添加可学习提示模板。** 在描述前插入若干占位符（默认为 `X X X X`），这些占位符在训练过程中会被优化为对 ReID 任务最有利的语义引导词。

**第二步：添加模态特定前缀。** 在描述前加上一段说明当前模态特性的固定文字：

| 模态 | 前缀含义 |
|------|---------|
| RGB（可见光） | "一张在可见光谱下的人物图像，捕捉了自然颜色和精细细节" |
| NIR（近红外） | "一张在近红外光谱下的人物图像，捕捉了对比度和表面反射特性" |
| TIR（热红外） | "一张在热红外光谱下的人物图像，捕捉了热辐射和温度梯度" |

经过预处理后，一段原本通用的描述就变成了一段**模态敏感的增强描述**。例如 RGB 模态的最终文本形如：

> "An image of a [X X X X] person in the visible spectrum, capturing natural colors and fine details: The female is wearing a white dress with a black belt"

### 1.3 文本编码：从文字到数字

文字描述本身无法直接被神经网络处理，需要转化为数值向量。项目采用**离线预编码**的方式：提前用 CLIP 文本编码器将所有描述编码为 512 维的特征向量并保存。训练和推理时直接加载这些向量，避免重复编码的时间开销。

最终，每个样本在被送入模型之前，携带的文本信息是：

| 键 | 内容 | 形状 |
|----|------|------|
| RGB | 可见光描述的特征向量 | 每个样本 512 维 |
| NIR | 近红外描述的特征向量 | 每个样本 512 维 |
| TIR | 热红外描述的特征向量 | 每个样本 512 维 |

## 二、训练阶段：文本如何参与模型学习

训练阶段的文本使用可以概括为四个步骤：**提取 → 融合 → 增强 → 优化**。

### 2.1 第一步：视觉特征提取

三种模态的图像（RGB、NIR、TIR）分别通过共享的 CLIP ViT-B/16 骨干网络，各自得到一个 512 维的视觉全局特征。如果启用了多尺度 MoE（IDEA01），这些特征还会经过多尺度滑动窗口和专家网络的增强。

### 2.2 第二步：三模态视觉融合

三个模态的视觉特征通过 AAM（聚合注意力模块）融合为一个 1536 维的全局融合特征。这个特征同时包含了三种模态的信息，是后续所有处理的基础。

### 2.3 第三步：文本语义注入（CMTF）

这是训练阶段文本被使用的**核心环节**。全局融合特征在此处接受文本语义的增强，具体过程为：

**（1）分模态文本投影。** 三路文本特征（RGB 文本、NIR 文本、TIR 文本）各自通过一个独立的适配器网络，从 512 维投影到 1536 维，使其与视觉融合特征的维度对齐。使用独立适配器（而非共享）是为了保留不同模态文本的语义特异性。

**（2）文本调制器聚合。** 将三路投影后的文本特征取平均，得到一个综合的文本调制信号。这个信号包含了三种模态文本的统一语义信息。

**（3）门控残差增强。** 将文本调制信号通过 Sigmoid 函数压缩到 0~1 范围，作为"门控信号"。然后将视觉融合特征逐元素乘以门控信号，再乘以一个融合权重 α（默认 0.3），最后以残差方式加回原始视觉特征。

用自然语言描述就是：

> 文本告诉模型"这个人穿红衣服、背黑包"→ 模型据此判断视觉特征中哪些维度该加强、哪些该保持 → 选择性地增强相关维度 → 同时保留原始视觉信息不被破坏。

**为什么采用门控残差设计？** 两个原因：一是门控机制让文本只增强与语义相关的特征维度，而非无差别地修改所有维度；二是残差结构保证了即使文本质量不佳（如描述错误），原始视觉特征也不会被严重损害。

项目还支持另外两种备选的融合策略（注意力融合和拼接融合），但残差门控融合是推荐的默认方式。

### 2.4 第四步：损失计算与参数优化

增强后的融合特征经过 BNNeck（批归一化颈部）和分类头，计算 ID 损失（交叉熵）和 Triplet 损失（三元组度量学习损失）。这些损失的梯度会反向传播，同时优化视觉骨干、AAM 融合模块、文本适配器和分类头的参数。

### 2.5 训练阶段数据流总结

```text
 三种模态图像 ──→ CLIP 骨干 ──→ 三路视觉特征 ──→ AAM 融合 ──→ 全局融合特征
                                                                  ↓
 三路文本特征 ──→ 分模态适配器 ──→ 聚合 ──→ 门控信号 ──────→ 门控残差增强
                                                                  ↓
                                                          增强后的融合特征
                                                                  ↓
                                                    BNNeck → 分类头 → Loss
```

**关键结论**：训练阶段，文本在三模态融合**之后**被注入，作用对象是**全局融合特征**（一个整体），目的是促进模型学习跨模态的语义一致性表征。

## 三、推理阶段：文本如何参与特征校正

推理阶段的文本使用策略与训练阶段截然不同，采用的是**模态内语义引导（IMSG）**。

### 3.1 设计意图

推理时面对的是真实场景，某个模态可能退化（如夜间 RGB 噪声严重、TIR 分辨率低）。如果仍然在融合后处理，退化模态的噪声已经"污染"了全局特征。因此推理阶段的策略是：**在融合之前，对每个模态单独进行文本引导校正**。

### 3.2 设计流程

推理阶段的设计流程分为两个阶段：

**阶段一：模态内引导。** 每个模态的视觉特征与其对应的文本特征配对，分别通过一个名为 SafeModalGuidance 的引导网络。该网络的工作方式为：

1. **分布对齐**：将视觉特征和文本特征分别归一化，然后将文本特征通过线性投影对齐到视觉空间
2. **门控信号生成**：将对齐后的视觉和文本特征拼接，送入一个两层 MLP + Sigmoid 网络，输出一个 0~1 之间的门控信号，表示"每个维度需要多大程度的增强"
3. **残差增强**：将视觉特征乘以门控信号，再乘以一个很小的增强幅度 β（初始仅为 0.1），以残差方式加回原始特征
4. **数值安全保护**：对输出进行裁剪，防止数值爆炸

用自然语言描述就是：

> RGB 文本告诉模型"这个人穿红衣服"→ 模型发现 RGB 视觉特征中"颜色相关维度"偏弱 → 通过门控信号选择性地微调增强 → 增强幅度极小（0.1），确保不会过度修改。

**阶段二：三模态拼接。** 三个模态各自引导增强后的特征拼接为 1536 维的最终特征，用于检索匹配。

### 3.3 与训练阶段的核心区别

| 维度 | 训练阶段 | 推理阶段 |
|------|---------|---------|
| **文本作用时机** | 融合**之后** | 拼接**之前** |
| **文本作用对象** | 一个全局融合特征 | 三个独立的模态特征 |
| **增强幅度** | α = 0.3（较大） | β = 0.1（很小，保守） |
| **模态间关系** | 三路文本合力增强一个整体 | 每路文本独立增强对应模态 |
| **设计目的** | 教模型学会跨模态语义对齐 | 对每个模态独立做考前补强 |

**为什么要这样设计？**

- 训练阶段的目标是**学习**，需要跨模态的深度语义交互，所以在全局层面注入文本
- 推理阶段的目标是**应用**，需要对每个模态的质量独立评估和校正，所以在单模态层面进行轻量引导

### 3.4 推理阶段数据流总结（设计意图）

```text
RGB 图像 ──→ CLIP 骨干 ──→ RGB 视觉特征 ──→ SafeModalGuidance(RGB文本) ──→ RGB 增强特征 ──┐
NIR 图像 ──→ CLIP 骨干 ──→ NIR 视觉特征 ──→ SafeModalGuidance(NIR文本) ──→ NIR 增强特征 ──┤── 拼接 → 检索
TIR 图像 ──→ CLIP 骨干 ──→ TIR 视觉特征 ──→ SafeModalGuidance(TIR文本) ──→ TIR 增强特征 ──┘
```

## 四、当前实现状态：一个关键缺陷

### 4.1 问题描述

经过逐行代码审查，发现推理/验证阶段存在一个**传参遗漏**：

- 数据加载层面：文本特征已被正确加载、编码，并随 batch 返回 ✅
- 调度层面：`processor.py` 中正确从 batch 中解析出了文本特征 ✅
- **但在调用模型时，文本特征没有被传递给模型** ❌

具体来说，训练阶段的模型调用包含了 `text_features` 参数，而验证/推理阶段的模型调用省略了这个参数。由于模型的 `forward()` 方法中 `text_features` 的默认值是 `None`，当它为 `None` 时，IMSG 引导模块的条件判断不满足，直接使用了原始视觉特征，相当于引导功能被静默跳过。

### 4.2 问题影响

| 环节 | 训练阶段 | 推理/验证阶段 |
|------|---------|-------------|
| 数据层：文本加载与编码 | ✅ 正常 | ✅ 正常 |
| 调度层：文本从 batch 中提取 | ✅ 正常 | ✅ 正常 |
| 调度层：文本传入模型 | ✅ 已传入 | ❌ **遗漏** |
| 模型层：文本功能生效 | ✅ CMTF 生效 | ❌ IMSG 未生效 |
| 最终效果 | 文本增强全局融合特征 | 仅使用原始视觉特征 |

### 4.3 修复方案

这是一个**单行代码修复**的问题。需要在 `engine/processor.py` 的验证循环和推理函数中，将模型调用从：

> `model(img, cam_label=..., view_label=...)`

改为：

> `model(img, cam_label=..., view_label=..., text_features=text_features)`

即补上遗漏的 `text_features` 参数。修复后，推理阶段的 IMSG 模态内引导将正常工作，每个模态的视觉特征将被对应的文本语义信号进行微调校正。

### 4.4 影响范围

需要修改的位置共三处，均在 `engine/processor.py` 中：

1. **非分布式验证循环**（`do_train` 函数内部的验证部分）
2. **分布式验证循环**（`do_train` 函数内部的分布式验证部分）
3. **独立推理函数**（`do_inference` 函数）

## 六、全文总结

### 文本的完整生命周期

```text
QwenVL 自动标注 → 模态前缀 + 提示模板预处理 → CLIP 编码为 512 维向量
                                                       ↓
                                      ┌────────────────┴────────────────┐
                                      ↓                                 ↓
                                  训练阶段                           推理阶段
                            AAM 融合后注入文本              （设计）融合前逐模态引导
                            全局语义增强                    （实际）⚠️ 文本未被传入模型
                            → 学习跨模态一致性               → 引导功能静默跳过
```

### 两个阶段的本质区别

- **训练阶段**像是"课堂统一授课"：文本面向融合后的全局特征，统一传授语义知识，帮助模型学会"三种模态看到的是同一个人"
- **推理阶段**像是"考前私教辅导"：文本面向每个模态的独立特征，针对各自的薄弱环节进行微调补强，且增强幅度极小以确保安全

### 当前状态

训练阶段的文本融合功能完整可用；推理阶段的模态内引导功能因传参遗漏暂未生效，修复难度极低（补上一个函数参数即可）。

## 附录：一个完整的具体示例

> 以下以 RGBNT201 数据集中**编号为 000042 的行人、摄像头 cam1 拍摄的第 1 帧**为例，完整展示文本特征从诞生到发挥作用的全部过程。所有数值均为简化示意，用于帮助理解数据流动方向。

---

### 第 1 步：磁盘上的原始数据

这个人有三张图像，分别拍摄于不同的光谱：

| 模态 | 文件路径 | 图像内容（人眼直觉） |
|------|---------|-------------------|
| RGB（可见光） | `train_171/RGB/000042_cam1_00001.jpg` | 彩色图，可以看到白色上衣、蓝色牛仔裤、黑色双肩包 |
| NI（近红外） | `train_171/NI/000042_cam1_00001.jpg` | 灰度图，衣服纹理和材质对比度较强，颜色信息消失 |
| TI（热红外） | `train_171/TI/000042_cam1_00001.jpg` | 热力图，人体轮廓发亮（体温高），背包区域偏暗（温度低） |

同时，数据集的 `text/` 目录中有三份 JSON 文件，其中记录着 QwenVL 自动生成的描述：

| 文件 | 该图像对应的描述（英文原文） |
|------|--------------------------|
| `train_RGB.json` | "A young woman wearing a white T-shirt, blue jeans, and a black backpack, walking in a campus area" |
| `train_NI.json` | "A person with a textured top showing clear fabric patterns, carrying a bag with distinct strap reflections" |
| `train_TI.json` | "A warm human figure with cooler regions on the back indicating a carried object, lower limbs show moderate heat" |

注意三种模态对同一个人的描述侧重点完全不同：
- RGB 描述关注**颜色和物品**（白色上衣、蓝色牛仔裤、黑色背包）
- NIR 描述关注**材质和反射**（织物纹理、背带反射）
- TIR 描述关注**温度和轮廓**（背部凉区=背包、下肢温度适中）

---

### 第 2 步：文本预处理——给每段描述加上"模态身份证"

系统读取原始描述后，会为每段描述添加**模态前缀**和**可学习提示模板**，构建出增强描述：

**RGB 增强描述**：

> An image of a **X X X X** person **in the visible spectrum, capturing natural colors and fine details**: A young woman wearing a white T-shirt, blue jeans, and a black backpack, walking in a campus area

**NIR 增强描述**：

> An image of a **X X X X** person **in the near infrared spectrum, capturing contrasts and surface reflectance**: A person with a textured top showing clear fabric patterns, carrying a bag with distinct strap reflections

**TIR 增强描述**：

> An image of a **X X X X** person **in the thermal infrared spectrum, capturing heat emissions as temperature gradients**: A warm human figure with cooler regions on the back indicating a carried object, lower limbs show moderate heat

每段描述现在由三部分组成：
1. **可学习提示**（`X X X X`）——在训练中会自动优化
2. **模态前缀**（粗体部分）——告诉编码器"这是哪种光谱下的观察"
3. **原始描述**——QwenVL 生成的具体内容

---

### 第 3 步：文本编码——从一段话变成一串数字

三段增强描述分别通过 CLIP 文本编码器，各自被压缩为一个 **512 维的数值向量**。可以想象为：一段几十个词的句子，被浓缩成了 512 个浮点数。

| 模态 | 编码前 | 编码后（示意） |
|------|-------|--------------|
| RGB | "An image of a X X X X person in the visible spectrum..." | `[0.12, -0.34, 0.87, ..., 0.45]`（共 512 个数） |
| NIR | "An image of a X X X X person in the near infrared..." | `[0.08, -0.21, 0.63, ..., 0.31]`（共 512 个数） |
| TIR | "An image of a X X X X person in the thermal infrared..." | `[-0.05, 0.42, 0.11, ..., 0.67]`（共 512 个数） |

这 512 个数里编码了"穿白衣服""背黑包""可见光谱"等所有语义信息。虽然人类看不懂这串数字，但神经网络可以从中精确读取语义含义。

这一步是**离线完成的**（提前算好存在磁盘上），训练时直接读取，不需要重新编码。

---

### 第 4 步：图像特征提取——模型"看"这三张图

训练开始后，三张图像被送入共享的 CLIP ViT-B/16 骨干网络。骨干网络对每张图像做了以下事情：

1. 将图像切成 16×16 的小块（patch），每个小块被编码为一个 512 维的向量
2. 所有小块的向量加上一个特殊的"全局汇总标记"（CLS token），通过 12 层 Transformer 进行信息交互
3. 最终取 CLS token 的输出作为这张图像的**全局特征**

如果启用了多尺度 MoE（IDEA01），CLS token 还会被多尺度滑动窗口提取的细粒度特征增强。

最终得到三个视觉全局特征：

| 模态 | 特征（示意） | 主要编码的信息 |
|------|------------|--------------|
| RGB 视觉特征 | `[0.55, 0.23, -0.18, ..., 0.41]`（512 维） | 颜色、纹理、空间布局 |
| NIR 视觉特征 | `[0.33, -0.12, 0.45, ..., 0.28]`（512 维） | 材质反射、对比度 |
| TIR 视觉特征 | `[0.11, 0.67, 0.03, ..., -0.22]`（512 维） | 温度分布、人体轮廓 |

---

### 第 5 步（训练阶段）：三模态融合

三个 512 维的视觉特征通过 AAM 融合模块，经过注意力交互后合并为一个 **1536 维的全局融合特征**：

```text
RGB特征 [512维] ──┐
NIR特征 [512维] ──┤── AAM 融合 ──→ 全局融合特征 [1536维]
TIR特征 [512维] ──┘
```

这 1536 维的特征相当于"三合一"，同时包含了颜色、材质和温度信息。但它还只是纯视觉的，尚未接受文本语义的增强。

---

### 第 6 步（训练阶段）：文本语义注入

现在，第 3 步准备好的三路文本特征开始发挥作用。

**（1）分模态投影：512 维 → 1536 维**

三路文本特征各自通过独立的适配器网络，从 512 维投影到 1536 维：

| 输入 | 适配器 | 输出 |
|------|-------|------|
| RGB 文本特征 [512维] | RGB 适配器 | RGB 文本调制器 [1536维] |
| NIR 文本特征 [512维] | NIR 适配器 | NIR 文本调制器 [1536维] |
| TIR 文本特征 [512维] | TIR 适配器 | TIR 文本调制器 [1536维] |

**（2）聚合为统一的调制信号**

三个调制器取平均，得到一个综合的文本调制信号 [1536维]。

**（3）门控残差增强**

以 1536 维中的**第 37 个维度**为例来说明门控过程（其他维度同理）：

| 环节 | 第 37 维的值 | 含义 |
|------|------------|------|
| 全局融合特征 | 0.72 | 这个维度的视觉信息强度 |
| 文本调制信号 | 1.85 | 三路文本对这个维度的综合语义评分 |
| 经过 Sigmoid | 0.86 | 压缩到 0~1，含义为"文本认为这个维度应该被增强 86%" |
| 门控乘积 | 0.72 × 0.86 = 0.62 | 视觉特征 × 门控信号 |
| 乘以权重 α | 0.62 × 0.3 = 0.19 | 控制增强幅度（30%的门控结果） |
| 残差加回 | 0.72 + 0.19 = **0.91** | 最终增强后的值 |

对比之下，假设**第 200 个维度**的文本调制信号为 -1.5（Sigmoid 后为 0.18），则：

| 环节 | 第 200 维的值 |
|------|-------------|
| 全局融合特征 | 0.45 |
| 门控信号（Sigmoid） | 0.18（文本认为这个维度不太重要） |
| 门控乘积 | 0.45 × 0.18 = 0.08 |
| 乘以权重 α | 0.08 × 0.3 = 0.02 |
| 残差加回 | 0.45 + 0.02 = **0.47**（几乎不变） |

可以看到：**文本"认为重要"的维度被显著增强（0.72→0.91），文本"认为不重要"的维度几乎不变（0.45→0.47）**。这就是门控机制的精髓——选择性增强。

---

### 第 7 步（训练阶段）：计算损失并更新参数

增强后的 1536 维融合特征经过 BNNeck 归一化，然后送入分类头。假设数据集共有 171 个行人身份，分类头会输出 171 个分数，表示模型认为这个特征属于哪个人。

- **ID 损失**：模型预测的身份应该是"第 42 号行人"，如果预测对了则损失小，预测错了则损失大
- **Triplet 损失**：同一个人的不同图像的特征应该接近，不同人的特征应该远离

这两个损失的梯度会反向传播，更新整条流水线上的所有可学习参数：CLIP 骨干、多尺度 MoE、AAM 融合模块、**文本适配器**和分类头。

---

### 第 5'步（推理阶段）：模态内引导（设计意图）

现在假设训练结束，模型进入推理阶段。同一个人 000042 出现在测试集中。推理阶段的处理与训练阶段不同：

**不再经过 AAM 融合，而是对每个模态单独施加文本引导**。

以 **RGB 模态**为例，SafeModalGuidance 引导网络的工作过程如下：

| 步骤 | 操作 | 直觉理解 |
|------|------|---------|
| 输入 | RGB 视觉特征 [512维] + RGB 文本特征 [512维] | "模型看到了什么" + "文字说了什么" |
| 分布对齐 | 两路特征分别归一化，文本投影到视觉空间 | 让视觉和文本"说同一种语言" |
| 拼接 | 将对齐后的两路特征拼接为 1024 维 | 合并信息 |
| 门控网络 | 1024维 → MLP → Sigmoid → 512 维门控信号 | 判断"RGB 视觉特征的哪些维度需要增强" |
| 残差增强 | 视觉特征 + 0.1 × 视觉特征 × 门控信号 | 极轻量地微调（幅度仅 10%） |

**一个具体的维度示例**：

假设 RGB 视觉特征的第 100 个维度值为 0.60，但由于夜间拍摄，该维度应该更高（因为文本说"穿白衣服"，白色相关维度应该强）。门控网络输出的第 100 维为 0.75，则：

> 增强值 = 0.60 + 0.1 × 0.60 × 0.75 = 0.60 + 0.045 = **0.645**

增幅非常微小（从 0.60 到 0.645），因为推理阶段追求**安全**——宁可少改，也不能改错。

同样的过程分别发生在 NIR 和 TIR 模态上，三者互不干扰：

```text
RGB 视觉特征 + RGB 文本 ──→ SafeModalGuidance ──→ RGB 增强特征 [512维]
NIR 视觉特征 + NIR 文本 ──→ SafeModalGuidance ──→ NIR 增强特征 [512维]
TIR 视觉特征 + TIR 文本 ──→ SafeModalGuidance ──→ TIR 增强特征 [512维]
                                                         ↓
                                               拼接为 1536 维最终特征
                                                         ↓
                                              与图库中所有人的特征比对
                                                         ↓
                                              输出：最相似的身份排名
```

### 当前实际状况

上述推理阶段的流程是**设计意图**，但由于 `processor.py` 中验证/推理循环调用模型时遗漏了 `text_features` 参数，实际执行时：

| 设计意图 | 实际执行 |
|---------|---------|
| RGB 文本引导 RGB 视觉特征 | ❌ RGB 文本未送达模型 |
| NIR 文本引导 NIR 视觉特征 | ❌ NIR 文本未送达模型 |
| TIR 文本引导 TIR 视觉特征 | ❌ TIR 文本未送达模型 |
| 增强后的三模态特征拼接 | 原始三模态特征直接拼接（无增强） |

模型在推理阶段等于只用了纯视觉特征，文本引导功能完全被跳过。修复后，000042 号行人的每个模态特征都将得到对应文本的微调校正，特别是在视觉退化的困难场景下，预期能提升检索准确率。
